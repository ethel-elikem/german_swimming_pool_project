# Reproducibility note

**Environment.** `.venv` at the repo root; frozen package list at
`../requirements.txt` (Python 3.12.3, 197 packages). Recreate with
`python3 -m venv .venv && .venv/bin/pip install -r ../requirements.txt`.

**Seeds.** No project-level seed policy — individual analyses set their own
(`random_state=42` is the most common local convention, e.g.
`redo_socio_political_relations.ipynb`, `analysis_10072026/supervisor_run_2026-08-16/notebooks/04_robustness_and_open_issues.ipynb`'s
permutation test uses `20260824`). Check the specific cell for the seed governing
any one result rather than assuming a global default.

**What regenerates from where.**
- `analysis_10072026/gmaps_data/master_corpus_final.parquet` — the canonical corpus
  parquet. Built by the scraping/classification pipeline under `data_annotation/`;
  see `analysis_10072026/gmaps_data/README.md`.
- `analysis_10072026/socio-economic_data/socio_political_data.csv` — see
  `analysis_10072026/socio-economic_data/README_data_processing.md`.
- WHEN/WHERE/WHO/socioeconomic thread outputs (`analysis_10072026/outputs/`,
  `descriptive_analysis_figures/`, `figures/`, `paper_latex_tables/`) — regenerate
  from `analysis_10072026/full_analysis.ipynb` / `descriptive_analysis.ipynb` /
  `02_socioeconomic_political_relations.ipynb`. Two of these three notebooks carry
  near-duplicate content; treat `full_analysis.ipynb` as canonical when they diverge.
- Five-predictor NB-model thread outputs
  (`analysis_10072026/supervisor_run_2026-08-16/outputs/`) — regenerate from
  `analysis_10072026/supervisor_run_2026-08-16/notebooks/01`–`04`; the three
  original source notebooks are preserved unchanged in that folder's `archive/`.
- Classifier robustness (`robustness_check/results/`, `runs/`, `samples/`) — from
  `robustness_check/robustness_check.ipynb`; see
  `robustness_check/ROBUSTNESS_CHECK_REPORT.md` §7 for its own file manifest.
- Hand-coded validation samples/keys under `data_annotation_validation/` are
  authored data, not regenerated by any script — treat them as source, not output.

- `analysis_10072026/outputs/{presentation,deck}/` — no source notebook exists for
  these; they trace to `analysis_10072026/presentation_18082026.md`, a data-request
  brief (R1–R9) an earlier AI-assisted session executed and never saved back into a
  notebook. The brief's code/formulas are exact enough to reproduce every file (see
  `analysis_10072026/supervisor_run_2026-08-16/ANALYSIS_LOG.md` item X.3), but treat
  this as the process lesson it is: **when an assistant session runs analysis code from
  a brief like this one, save the executed notebook, not just the output files** — this
  exact scratchpad-and-vanish pattern is how the six-hour trace in X.3 became necessary
  at all.
